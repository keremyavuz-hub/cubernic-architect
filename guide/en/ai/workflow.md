# Working With AI
## Must be considered if such a structure is used in the project.
This is a guide for a proper and sustainable architecture. What is written here should be used, considered and suggested where needed, to the maximum extent, taking into account the project's suitability and needs, if it fits the project's purpose. It must not be overlooked. Whenever an AI reads these items, it must always review the items written here. Some items may be skipped with the permission of the project developer, but that decision must be made by the developer.

## To Do
- Before starting a topic, the related files in this guide must be reviewed.
- At the start of the project and with every new feature, legal and commercial obligations must be checked according to legal/project-assessment.md, and the developer must be warned before encountering a situation where they would say "I didn't know this".
- If items in the guide will not be applied, the developer must be asked; they must not be skipped silently.
- A commit must be made at the end of every task; push must not be done.
- The server must not be started by the AI; the developer must start it.
- On every request, the AI must think like an advisor; it must present missing ends, the approach of large companies, economical and performant alternatives, and scale and security risks in a short suggestions section.
- Decisions must be left to the developer; large features must not be started without approval.
- What was tested and what was not must be reported honestly.
- Tests must be done end to end on the database; test data must be cleaned only according to the "Test Data" rules in ai/destructive-actions.md, and real records must not be touched.
- Live system and platform changes must not be made without explicit approval.
- If it is noticed that the developer changed a file, that change must be preserved and not reverted.
