# Documentation
## Must be considered if such a structure is used in the project.
This is a guide for a proper and sustainable architecture. What is written here should be used, considered and suggested where needed, to the maximum extent, taking into account the project's suitability and needs, if it fits the project's purpose. It must not be overlooked. Whenever an AI reads these items, it must always review the items written here. Some items may be skipped with the permission of the project developer, but that decision must be made by the developer.

## To Do
- A document describing the current state of the system section by section, item by item (e.g. docs/SISTEM.md) must be kept.
- The system document must be updated after every feature.
- A dated work log (e.g. docs/GUNLUK.md) must be kept, with the newest entry at the top.
- For each task, the log must state what was done, why it was done, which files changed and what remains open.
- The system document must have a to-do section, and pending platform settings must also be written there.
- Every vulnerability and lesson found must be added to the relevant file in this architecture guide.
- If there is no suitable file in the guide, a new file or folder must be created and added to the README file.
